# 第1周例会总结（中文）

## 一、项目目标

我的任务是完成 IIIF 数据流水线的前半部分：调查 IIIF 提供机构，发现并获取 Manifest（资源清单文件），按版权规则筛选资源，规范化标识符、日期、地点、版权和来源等元数据，并将结果转换为团队的公共数据模式后交付下游。

## 二、当前进展

1. 已学习 IIIF、Manifest、Change Discovery API（变更发现接口）、Activity Stream（活动流）和 IIIF Registry（登记目录）的基本概念。
2. 已在原始三台流水线机器的基础上细化模块边界，并明确日志应贯穿全部环节。
3. 已调整前四周计划，将小样本流程贯通提前到第二周，以便尽早发现模块接口问题。
4. Codex 机构分拣器尚未实现。目前只明确其输入、输出、测试样本和验收条件。

## 三、当前流水线设计

```text
IIIF机构存储分拣器
→ IIIF入口地址访问与有效性检查
→ IIIF资源发现器
→ Manifest获取与结构校验器
→ 版权识别与筛选器
→ 资源内容读取与元数据规范化器
→ 公共数据模式校验与导出器
→ 下游
```

各模块职责如下：

- 机构分拣器：保存机构信息，并根据任务要求选择本次处理的机构及其 IIIF 数据入口。
- 地址访问器：检查入口能否访问，记录状态码、访问时间和失败原因。
- 资源发现器：遍历活动流或集合的分页，提取并去重 Manifest 地址，同时保留来源和活动信息。它汇总 Manifest 地址，不合并 Manifest 内容。
- Manifest 获取与校验器：获取 JSON 数据，检查其能否解析以及是否具有基本 IIIF 结构。
- 版权筛选器：保存原始版权声明，进行统一分类，并按照导师确认的规则决定是否保留资源。
- 内容读取与规范化器：提取并规范化标识符、日期、地点、版权和来源等字段，同时保留原始值和缺失状态。
- 公共数据模式校验与导出器：检查字段名称、类型、必需字段和来源追踪信息，然后按下游要求导出。
- 日志：贯穿全部环节，记录来源、处理时间、处理状态和失败原因。
