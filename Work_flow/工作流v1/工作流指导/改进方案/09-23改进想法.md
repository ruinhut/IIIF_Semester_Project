## 一、基本原则与实施顺序

当前工作的第一优先级是先跑通 Module 1--7，形成一条能够从机构清单运行到公共数据模式导出的完整初代流水线。初代流水线跑通并形成可复现基线后，再集中迭代 Module 3 的资源发现与泛化能力。下列网络自动发现和 LLM 辅助方案属于后续升级，不应延迟初代流水线。

当前实施顺序为：

\begin{center}
完成 Module 1--7
$\rightarrow$ 形成可复现的小规模端到端结果
$\rightarrow$ 重点迭代 Module 3
$\rightarrow$ 重新进行留出机构测试
$\rightarrow$ 再考虑 Module 1 网络发现与 LLM 辅助
\end{center}

## 二、当前 Module 3 的主要问题

2026-09-25 的基线实验将 94 个机构按机构域名划分为 75 个开发机构和 19 个留出测试机构。Module 2 检查了两组机构的全部入口；冻结后的 Module 3 在留出集中解析成功 2 个机构，共发现 19 个 Manifest URL，机构成功率为 10.5\%。

当前瓶颈不是缺少入口遍历，而是无法把许多机构入口转换为可批量验证的 Manifest：

1. 机构 API 的调用、认证、字段读取和分页方式尚未系统支持；
2. 普通搜索页面和搜索 API 尚不能稳定遍历到藏品详情页；
3. 尚不能通用地枚举 object ID、ARK、UUID、shelfmark 等标识符；
4. 尚未建立由标识符生成并验证 Manifest URL 的模板机制；
5. 入口角色分类较粗，同为机构网站的页面可能属于不同平台和访问机制；
6. HTML 探索采用有限深度和数量上限，动态页面、跨域 IIIF 服务和隐藏接口可能被遗漏。

Module 3 是确定性规则程序。这里的“学习”是把开发集中验证成功的规则、证据和测试保存到版本化适配器库中，不是程序自动更新模型参数。

## 三、Module 3 的重点改进方向

### 1. 机构 API 适配

识别公开 API 的入口、认证要求、分页参数、藏品字段和速率限制。优先实现不需要密钥或可通过公开方式获得密钥的接口。API 返回值必须保留来源和原始标识符。

### 2. 搜索接口遍历

支持普通搜索 API、HTML 搜索结果、站点地图和藏品详情页。遍历必须具有页数、请求速率和最大结果数量限制，并能够断点续跑。

### 3. 标识符枚举

从 API、Collection、搜索结果或页面结构中提取 object ID、ARK、UUID、shelfmark 等标识符，记录标识符类型、来源页面和所属机构。

### 4. Manifest URL 模板

建立可配置模板，将机构标识符转换为候选 Manifest URL，例如：

\begin{center}
https://example.org/iiif/\{object\_id\}/manifest
\end{center}

所有生成的候选 URL 都必须经过网络访问、JSON 解析和 IIIF 类型校验，不能仅凭字符串形式认定为 Manifest。

### 5. 可复用适配器注册表

适配器应按平台或接口模式组织，而不是把大量机构名称判断直接写入主程序。每个适配器至少记录：

- 识别条件；
- API 或搜索入口；
- 分页与标识符提取方法；
- Manifest URL 模板；
- 访问限制和所需密钥；
- 自动测试和成功证据；
- 适配器版本。

开发集用于编写和验证这些通用适配器。实现冻结后，再对留出机构运行，不为测试机构临时增加专用规则。

## 四、初代流水线完成后的其他升级

### Module 1：候选提供者发现器

在 Module 1 前或内部增加 Provider Discovery Scout：

1. 优先读取 IIIF Registry、官方指南、社区清单和项目人工记录；
2. 再通过搜索引擎 API、站点地图和有限网页探索发现可能的新机构和入口；
3. 保存候选机构、候选 URL、来源、发现时间、证据和置信度；
4. 搜索结果仅作为候选线索，仍需交给 Module 1 整理并由 Module 2 验证。

### LLM 辅助分析

当标准解析器和已验证适配器均失败时，LLM 可以阅读机构页面或 API 文档，提出候选入口、接口类型、URL 模板或适配器草案。LLM 输出不能直接成为正式采集结果，必须经过 Module 2 网络检查、IIIF 结构校验、有限遍历、自动测试和必要的人工审核。

## 五、泛化能力验证

继续使用未参与适配器开发的机构作为留出测试集，至少报告：

- 具有可访问入口的机构数；
- 成功发现有效 Manifest 的机构比例；
- 每种入口类型和适配器的覆盖机构数；
- 有效 Manifest 及页面图像数量；
- 错误候选比例；
- 新增专用适配器数量；
- 人工审核工作量；
- 遍历上限、超时和权限限制。

负面结果只能解释为“在统一限制和当前策略下未找到 Manifest”，不能证明机构没有 IIIF 资源。
