## 二、每页具体内容

### 第1页：整体八模块流水线

**英文标题：Modular IIIF Harvesting Pipeline**

页面目标句：Collect scattered heritage resources and deliver linked images, metadata and institutional reference texts for downstream OCR work.

主体是一张完整流水线图，保留八模块顺序：

```text
Registry | Official guides | Community lists | Maintained entries
                              |
                              v
M1 Provider census and selection
 -> M2 Endpoint checks
 -> M3 Manifest discovery
 -> M4 Manifest retrieval and validation
 -> M5 Rights classification
 -> M6 Metadata normalization and reference linking
 -> M7 Common-schema export
 -> M8 Image and reference-text download
                              |
                              v
              Images + linked JSON + available reference text
```

图旁补充：One command runs the selected modules; outputs and logs are retained at each stage.

讲述重点是数据如何贯穿各阶段。M3是发现瓶颈，M7–8是下游交付端；不在本页介绍函数和全部配置。

### 第2页：Module 1–2——来源整理与入口检查

**英文标题：Modules 1–2: Provider Census and Endpoint Checks**

页面文字：

- **Module 1:** Combine sources, retain candidate endpoints and provenance, and select providers for a run.
- **Module 2:** Check each supplied endpoint and record accessibility, HTTP status, elapsed time, content type and JSON parsing results.

按要求放三张图片：

1. **来源汇总图：** 四类来源进入统一清单，显示机构名称、来源依据和候选链接的保留。
2. **选择与多入口图：** 一个机构对应多个入口；展示按机构名或 `all` 选择本次输入，可用真实清单的精简截图。
3. **入口检查结果图：** 展示各入口的状态、耗时、内容类型和解析结果，可用精简表格配统计图。

本页统计：M1选择100个来源，保留139个候选入口；M2检查139个入口，118个HTTP成功，88/100个来源有可达入口。响应分类为30个JSON、8个XML、80个HTML，另21个不可达、受限或超出响应限制；29/100个来源有初始JSON入口。

页面结论：Preserve multiple routes and distinguish accessibility from resource discovery.

需要说明：XML/HTML不等于不可用；M2检查入口，不负责证明已经发现文献或完整目录。

### 第3页：Module 3——Manifest发现

**英文标题：Module 3: Manifest Discovery**

按“重要性—能力—完成情况”写：

**重要性：** A reachable homepage does not necessarily expose a directly traversable Manifest catalogue. Discovery determines which providers can contribute resources downstream.

**实际能力：**

- Direct Manifests, IIIF Collections and pagination, and Change Discovery streams.
- HTML links and embedded data; JSON, HTML and XML/RSS/OAI catalogue recipes.
- Reusable pagination, identifier extraction, detail lookup and Manifest URL templates.

用一条实例解释：

```text
EPFL Plume -> Omeka S catalogue API -> o:id -> IIIF Manifest -> Canvas
```

Plume藏品页本来就有IIIF链接；API用于提高目录枚举效率，不是因为Plume没有IIIF。

**完成情况：** 历史100/127条成功证据用于固定本轮100个来源，不是当前成功率。11月6日实跑中，98/100个来源找到Manifest URL；共280条来源–Manifest观测，对应274个唯一URL。每个来源上限3份，不能据此推断全馆数量或陌生机构泛化率。

本轮M4–7最终97/100个来源产生图像文献输出。逐机构统计使用100个来源的结果；主图可显示前20名产出，另备五张逐来源阶段结果图覆盖全部100条。

页面结论：Reusable skills and provider configuration improve coverage, while complete catalogue enumeration remains a separate challenge.

LLM接口状态与后续评估放第7页，避免把历史覆盖成绩归因于新接入的模型接口。

### 第4页：Module 4–6——校验、权利分类与元数据整理

**英文标题：Modules 4–6: Validation, Rights and Normalization**

| 模块 | 页面文字 | 同批结果 |
|---|---|---|
| M4 | Fetch raw Manifests, validate basic IIIF structure and inventory image resources. | 280条输入观测中275条通过图像流水线校验；对应269个唯一有效URL |
| M5 | Preserve rights evidence and distinguish research retention from reuse eligibility. | 275/275条研究保留；237条未获准公开再利用、其中132条未知版权，均继续下游 |
| M6 | Normalize metadata and link images with declared institutional reference texts. | 275条文献均研究可用；44,915条图像关联，7,232条文本描述 |

统计来自2026-11-06同批100来源实跑。来源级输出率为97/100；275/275是已经进入M5的有效文献研究保留率，两个分母分开呈现。缺日期/地点不阻断研究使用，公开再利用许可也不再影响M6完整性判断。

**图片内容：** 三阶段处理示意；权利分类统计或真实权利字段；规范化记录的关键字段片段。

```text
获取与校验Manifest -> 权利分类与证据保留 -> 规范化文献/图像/机构文本
```

需要讲清楚：按项目策略，unknown及公开再利用被exclude的资源进入研究下游，同时保留原始声明与限制。unknown不等于无版权。这是权利信息分类，不是程序完成法律审查。

页面结论：Validated resources retain their provenance, rights restrictions and normalized metadata.

### 第5页：Module 7–8——统一输出、下载与OCR交接

**英文标题：Modules 7–8: Linked Outputs and Downloads**

页面文字：

- **Module 7:** Validate the common output schema and preserve document–image–reference associations.
- **Module 8:** Download an example or all exported images, with linked JSON records and retrievable reference text.

左侧放简化关联结构，右侧放真实图片与对应机构文本：

```text
common_records：文献主记录，record_id
 |
 |-> common_media：每页图像，record_id + resource_id + Canvas ID
 |-> ocr_document_profiles：文献OCR画像，record_id
 +-> institution_reference_texts：机构文本，record_id
                    |
                    +-> 已知页面：resource_id / Canvas -> 对应图像
```

一份Manifest可对应多张图片；文献级文本不能确定页面时，不生成虚假的逐页关联。

**样例：** 林茨 `AC05304281` 的Canvas 21，图像与ALTO页面均为2882×4629，159个词框在图像范围内。展示正文图、少量文本和对应ID，不铺满全部JSON。

**文件展示：** 图片旁附 `common_record.json`、`common_media.json`、`ocr_document_profile.json` 三份基础JSON；有参考文本时另附原始文本、纯文本和 `institution_reference_texts.json`。

**分类与统计：** 说明 `with_reference`、`without_reference`、`reference_failed`。本轮M7导出275条文献观测、44,915条图像关联、275份画像及7,232条文本描述；图像下载URL去重后44,252个。M8未运行，不给出本轮下载成功率。林茨配对样例来自10月22日历史验证，不能算作本轮新下载。

页面结论：Arsha can use explicitly linked page images and institutional texts without reconstructing the associations from filenames.

机构OCR/转录不自动等于人工校正答案；OCR画像中无证据的语言、字体或扫描情况保留未知。

### 第6页：完整流水线演示视频

**英文标题：End-to-End Demonstration**

主体放视频，页面文字只保留输入范围、启动命令和结果摘要。

```text
展示输入与参数 -> 一条启动命令
 -> M1 -> M2 -> M3 -> M4 -> M5 -> M6 -> M7 -> M8
 -> 打开本次目录 -> 图片、JSON与可用参考文本 -> 摘要和分类
```

可用于录制固定种子交接演示的命令，在仓库根目录运行：

```text
python pipeline.py --modules 1-8 --manifest-url https://plume.epfl.ch/iiif/3/44/manifest --max-manifests 1 --download example
```

画面注明“固定种子的模块交接演示”。要展示从机构首页或目录发现Manifest，应选已有验证方法的机构并使用 `--institution`，不把两种输入混淆。

2026-11-05已验证的是M1–3执行后续跑M4–8：1份有效Manifest、415条图像记录、1张图片和3份JSON。录制“一条命令跑全程”前，应在新目录实际执行并保存对应日志；不能将分段记录冒充一次未执行的运行。

若视频采用EPFL无页面参考文本的样例，第5页林茨配对样例标明来自另一批输出。等待过程可以剪辑或加速并注明；目录、图片和日志对应同一次演示运行。

### 第7页：后续改进——LLM发现与UI可视化

**英文标题：Next Steps: LLM Discovery and Visual Interface**

左右两部分展示，当前问题与后续计划合在本页。

**左侧：完善并验证Module 3的LLM辅助发现。**

- 调查未知机构的平台、官方指南和目录API，提出候选获取方法。
- 实际请求、验证候选Manifest，成功后保存方法与证据，后续复用。
- 用未参与方法开发的机构评估发现成功率、调查成本、失败原因和复用效果。

```text
已有方法未解决 -> LLM调查并提出方法 -> 确定性HTTP/JSON/IIIF检查
                                         |-> 成功：保存 -> 后续复用
                                         +-> 失败：保留原因与未解决状态
```

状态短句：LLM interface implemented; autonomous discovery performance evaluation pending.

接口、预算控制、验证与保存逻辑已实现；真实付费模型对未知机构的效果尚未评估，不把接口实现画成已经证明泛化有效。

**右侧：UI与可视化构思。**

- 选择机构、模块范围、下载模式，配置自己的API服务与令牌。
- 查看阶段进度、数量、错误原因和日志。
- 浏览来源覆盖、Manifest及图像统计，打开图片、元数据和参考文本。

```text
输入设置 -> 启动运行 -> 进度与错误 -> 统计结果 -> 图文浏览/下载
```

UI目前未开发。两个改进方向分别降低新来源接入成本和程序使用门槛。
