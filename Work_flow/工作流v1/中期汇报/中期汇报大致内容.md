# 中期汇报大致内容

整理：2026-11-06。压缩自《IIIF项目中期报告_2026-11-02.md》，补充11月5日启动器与LLM接口状态。按已确认的七页顺序组织；流程图均用文字与箭头表示。

主讲数量已更新为11月6日100来源新实跑：M1–7运行、M8不运行；不再用旧七机构样本作为总览。研究用途与公开再利用资格分别处理。

## 1. 整体八模块流水线

目标是将分散机构的文化遗产资源转成可追溯、保留权利信息的统一数据，交给Arsha进行下游OCR实验。当前任务是采集与交接。

```text
Registry | IIIF官方指南 | 社区清单 | 项目维护条目
                         |
                         v
M1 来源与选择 -> M2 入口检查 -> M3 Manifest发现
                                  |
                                  v
M6 元数据与文本整理 <- M5 权利分类 <- M4 Manifest获取与校验
       |
       v
M7 统一导出 -> M8 图片与可用参考文本下载 -> 下游OCR
```

八模块均已实现，有独立配置、输出和日志。统一命令行支持选择模块范围、独立运行目录和模块边界续跑。Manifest可描述一本多页文献，Canvas描述页面等展示单元，Manifest数与图片数不能混用。

## 2. Module 1–2：整理来源，检查入口

M1汇总清单，保留来源依据和每个机构的多个候选入口，按机构名称或 `all` 选择输入。M2逐入口记录可达性、HTTP状态、重定向、耗时、内容类型和JSON解析结果。

```text
多份清单 -> 机构记录 + 来源证据 + 多个入口 -> 本次机构选择
 -> 逐入口检查
       |-> 可达：保留响应与解析结果 -> M3
       +-> 不可达：保留失败原因
```

本轮100来源有139个候选入口，全部检查；118个HTTP成功，88/100个来源有可达入口，29/100个来源有初始JSON。检查结果包含30个JSON、8个XML、80个HTML，另21个不可达、受限或超出响应限制。非JSON不等于无效；“可以访问”不等于“已经发现文献”。

## 3. Module 3：关键发现能力与完成情况

机构首页未必提供可直接遍历的目录，Manifest可能在藏品页，或需要先经目录API获取ID。初版入口保留不全、网页遍历范围小和目录处理不足，曾导致漏检。

```text
按机构分组的M2结果
 |-> 原生IIIF：Manifest / Collection及分页 / Change Discovery
 |-> 网页：显式链接 / 嵌入数据 / 有界详情页遍历
 |-> 目录：JSON / HTML / XML / RSS / OAI
 |          -> 分页 -> ID或链接提取 -> 详情展开/URL模板
 +-> Manifest去重 + 来源证据 + 失败/截断记录 -> M4
```

通用代码负责操作，机构配置提供URL、字段、分页、模板和目录范围，知识文档保存依据。这些是能力类别，不是对每家机构无上限穷举的固定顺序。

```text
EPFL Plume -> Omeka S /api/items -> o:id
 -> /iiif/3/{identifier}/manifest -> Canvas -> 图像服务 -> 图片
```

Plume藏品页本来就有IIIF链接；Omeka S API是一种高效目录枚举方法，不替代IIIF。

截至2026-10-22的累计历史证据：

```text
原始94条：已验证67 + 未完成27
后补33条：已验证33
合计127条：有成功证据100 + 未完成27
```

100是来源条目，包含聚合平台、项目与同机构不同条目，不是去重后的100家机构或独立留出测试成功率。

本轮从历史100条成功来源中固定全部100条，每家最多取3份Manifest。M3为98/100个来源发现280条来源–Manifest观测，对应274个唯一URL；不能据此推算全馆总量。已保存方法的样本重放，不代表对陌生机构的泛化评测。

## 4. Module 4–6：校验、权利分类和规范化

```text
M4 保存原始Manifest -> 基本IIIF结构校验 -> 图像清单
 -> M5 权利分类与证据保留
       |-> 研究保留：包括unknown及公开再利用被exclude的资源 -> M6
       +-> 公开再利用合格子集：按当前策略单独标记

M6 -> 规范化文献 + 图像 + 机构参考文本描述及关联 -> M7
```

本轮M4强制重新获取：280条输入观测中275条通过图像流程校验，对应269个唯一有效Manifest URL。M5将275条全部研究保留；其中237条未获准公开再利用，包含132条未知版权，仍继续下游。M6将275条均规范化为研究可用记录，输出44,915条图像关联及7,232条文本描述。

unknown不等于无版权，exclude不等于从研究数据删除。M6已去掉“不允许公开再利用就算缺版权字段”的错误条件，并单独记录 `research_usable`。缺日期/地点只是描述信息不完整，不阻断研究使用。无证据的信息仍保留未知；全体图像扫描质量尚未作视觉评估。

## 5. Module 7–8：统一交付与OCR支持

M7校验并导出当前有版本的共同数据模式；最终模式仍需与团队对齐。M8下载一张样例或本次已导出的全部合格图片，以及能实际取得的页面参考文本。

```text
common_records.jsonl：文献主记录，record_id
 |-> common_media.jsonl：图片，record_id + resource_id + Canvas + URL
 |-> ocr_document_profiles.jsonl：文献OCR画像，record_id
 +-> institution_reference_texts.jsonl：机构OCR/转录及来源
       |-> 已知页面：resource_id / Canvas -> 对应图片
       +-> 文献级文本：resource_id为空，不制造逐页答案
```

每张成功图片附带 `common_record.json`、`common_media.json`、`ocr_document_profile.json`。有参考文本时，另附机构原始文本、纯文本与参考来源JSON。

```text
图片成功下载
 |-> 有页面文本声明 -> 获取成功：with_reference
 |                    获取失败：reference_failed
 +-> 未识别到可用于该页的文本声明：without_reference

图片下载失败 -> 失败日志
```

权利资格和参考文本可用性是独立维度。“未识别到文本”不证明机构从未提供文本。

本轮M7导出275条文献观测、44,915条图像关联、275份OCR画像和7,232条文本描述。图像下载URL去重后为44,252个；引用这些数字时区分来源观测和唯一对象。M8按要求未运行，没有本轮图片下载成功率。

可另展示10月22日已验证的林茨 `AC05304281` Canvas 21：图像与ALTO均为2882×4629，159个词框在范围内。这是历史图文配对示例，不是本轮新下载；文本声明的数量也不等于已取得的正确标签数量。

图文配对支持Arsha筛选训练或评估样本，但机构OCR不自动等于人工校正答案，坐标匹配也不证明识别准确率。BSB hOCR、FromThePage转录及EPFL无页面参考文本样例另有历史链路证据。

## 6. 全流程演示与验证

```text
一条启动命令 -> M1 -> M2 -> M3 -> M4 -> M5 -> M6 -> M7 -> M8
 -> 阶段摘要 -> 图片与JSON -> 可用文本与输出分类

本次目录/
 |-> configs/：配置快照
 |-> module_1/ ... module_8/：阶段输出与日志
 |-> module_4/raw_manifests/：原始Manifest
 +-> module_8/output/：图片、JSON、实际取得的文本
```

固定种子证明模块交接；从机构首页发现资源，需要另展示目录路线和日志。11月5日EPFL item 44已完成M1–3后续跑M4–8：1份有效Manifest、415条图像记录、1张图片及3份通过检查的JSON。该例不含页面参考文本，不与林茨样例混称同次运行。

同日八模块与运行器262项测试通过，另有12个子测试；其中21项新增测试覆盖LLM协议、验证、预算与复用。正式视频的一条命令运行仍应在录制前实跑留档；不把剪辑后的视频长度称为真实执行耗时。

11月6日又完成100来源的M1–7实跑：M1选择100，M2可达88，M3发现98，M4–7有图像文献输出97。未完成来源为莱比锡、威尔士国家图书馆和Northwestern本轮样本；原因分别包括网络请求错误、403/目录超时，以及抽取的Manifest没有图像正文。这不证明这些机构没有IIIF。M6修复后40项测试、M7的29项测试通过。

## 7. 当前问题与后续改进

### LLM辅助发现

未知平台调查和完整目录枚举仍是瓶颈。11月5日已实现可选LLM接口，支持用户自己的模型服务和本地令牌；已有方法先运行，未解决机构再进入有预算的调查。

```text
已有方法 -> 成功：正常下游
       +-> 未解决 -> 可选LLM读取公开证据、提出方法
                    -> 通用代码请求并检查HTTP/JSON/IIIF
                         |-> 成功：输出Manifest，保存方法和证据
                         |            +-> 后续重新验证并复用
                         +-> 失败：保留原因和未解决状态
```

模型提出候选，确定性检查决定接受，M4继续负责基本结构校验。保存方法是配置和经验复用，不是重新训练模型。

已用模拟模型服务结合真实EPFL公开请求，验证ID提取、Manifest获取、方法保存和无模型重用。尚无用户真实模型凭据，未评估付费模型自主调查未知机构的效果，不能称为泛化问题已经解决。

下一步使用未参与方法开发的机构评估发现成功率、请求数、耗时、成本与复用效果，并记录每条方法的目录范围、分页能力和停止原因。找到部分Manifest与完成全馆枚举分别评价。

### UI与可视化构思

```text
机构/模块/下载模式/可选API设置
 -> 启动或模块边界续跑 -> 进度、日志与错误
 -> 来源与资源统计 -> 图片、元数据及参考文本浏览/下载
```

UI目前未开发，目标是降低使用门槛。还需改善高清图像选择、外部AnnotationList/AnnotationPage文本覆盖和质量抽样；部分图像链接只是预览，不能统一声称取得原始分辨率。访问限制、迁移及超时等问题继续保留证据。
