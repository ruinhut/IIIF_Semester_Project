# IIIF 项目已完成工作与当前状态总结

整理日期：2026 年 10 月 23 日。最新机构扩展实测日期：2026 年 10 月 22 日。

本文依据本地代码、配置、测试结果及实际输出整理。本次是状态核对，没有重新联网收割全部机构。各项数量均注明统计范围，历史报告中的旧数字不作为当前全量结果。

## 1. 我们目前完成了什么

我们已经实现了 **Module 1–8 和统一运行器**，建立了从机构清单、入口检查、Manifest 发现，到权利分类、元数据规范化、图片与机构参考文本下载的完整链路。

已经完成的主要工作包括：

1. 设计模块化流水线，确定各模块的输入、输出和交接格式。
2. 整理机构来源，保留同一机构的多个入口及其来源证据。
3. 实现多种 Manifest 发现方法，并将验证过的方法保存为可执行配置和知识文档。
4. 修改权利处理策略，使 unknown 和 exclude 资源仍能进入研究用途的下游输出，同时保留限制标记。
5. 按 Arsha 的需求增加文献 OCR 特征描述，并建立文献、图片与机构参考文本的关联。
6. 实现图片、原始 OCR/转录文件和配套 JSON 的实际下载，以及有无参考文本的目录分类。
7. 编写自动测试、真实联网验收、命令行运行说明、中文与英文 README、周报和会议材料。

**当前核心瓶颈仍然是 Module 3：从不同机构的入口稳定地发现并完整枚举 Manifest。** 已知路线可以自动执行，但未知机构的调查还没有完全自动化。

## 2. 整条流水线如何工作

```text
机构来源清单与项目维护条目
        ↓
Module 1：整理机构及全部候选入口，选择本次处理对象
        ↓
Module 2：逐入口检查可访问性、响应类型和 JSON 解析情况
        ↓
Module 3：利用通用方法和机构配置发现 Manifest URL
        ↓
Module 4：获取原始 Manifest，校验基本结构并列出图像资源
        ↓
Module 5：识别权利，区分研究保留与公开再利用资格
        ↓
Module 6：提取、规范化文献、图像和机构参考文本信息
        ↓
Module 7：校验并导出共同数据格式和 OCR 交接文件
        ↓
Module 8：下载图片及可获取的参考文本，生成独立样本包
```

Manifest 通常描述一本书或一个数字对象，不一定只有一张图片。Canvas 是其中的页面或展示画布；图像资源记录、参考文本地址和实际下载文件分别统计。

### 各模块已实现的核心内容

| 模块 | 已完成的功能 | 主要输出或交接文件 |
|---|---|---|
| Module 1 | 合并 Registry、官方资源指南、社区清单及项目维护条目；规范化并按证据合并；保存多个候选链接；支持人为选择机构或 `all` | `providers.jsonl`、`selected_providers.jsonl`、`providers.csv` |
| Module 2 | 检查每个机构的每个候选入口；记录 HTTP 状态、重定向、最终 URL、耗时、内容类型、JSON 解析结果与失败原因 | `checked_entry_points.jsonl`，以及可访问、不可访问等分类结果 |
| Module 3 | 按机构组织多入口；发现和去重 Manifest URL；调用保存的通用技能与机构配置；记录路线、失败和截断 | `manifest_urls.jsonl`、`provider_discovery.jsonl`、`resolved_endpoints.jsonl`、`unresolved_providers.jsonl` |
| Module 4 | 下载并保留原始 Manifest；校验基本 Presentation 结构；生成 Canvas、图像主体与图像服务清单 | `validated_manifests.jsonl`、`manifest_resource_inventory.jsonl`、原始 JSON 缓存 |
| Module 5 | 提取原始权利证据和分类；保留研究用途资源；另列公开再利用子集 | `research_manifests.jsonl`、`research_resource_inventory.jsonl`、`reuse_eligible_manifests.jsonl` |
| Module 6 | 保留原始元数据；规范化标题、语言、日期、作者等字段；提取机构 OCR/转录的地址、格式、对齐范围与来源 | `normalized_records.jsonl`、`normalized_resources.jsonl`、`normalized_reference_texts.jsonl` |
| Module 7 | 校验数据结构和关联 ID；导出文献、图像、OCR 画像及参考文本；生成统计和候选页面 | `common_records.jsonl`、`common_media.jsonl`、`ocr_document_profiles.jsonl`、`institution_reference_texts.jsonl` |
| Module 8 | 提供下载单张例子和全部已导出图片两种命令；下载图片、配套 JSON 和可用参考文本；记录下载失败 | 图片样本包、原始参考文本、纯文本、`download_index.jsonl`、`download_summary.json` |

每个模块都具有独立配置、命令行入口、测试及日志。日志保存在相应配置指定的 `data/log/` 等目录，使用带运行时间的 TXT 文件。

统一运行器 `Pipeline_Runner` 负责按顺序执行模块，支持指定开始与结束模块，并保留运行记录。生产输出、独立验收输出、机构调查输出使用不同目录，不能假定所有最新文件都在同一个 `data/output/` 中。

## 3. Module 3 已经做了哪些实质改进

### 3.1 修正了最初的数据交接和发现策略

最初的问题包括：只保留少量入口、过于依赖首页直接暴露 IIIF、网页遍历预算过小，以及缺少平台目录 API 的识别和处理。

我们已经进行的改进是：

- Module 1 保留多个入口及其来源，Module 2 对这些入口分别检查，Module 3 按机构组织检查结果。
- 增加 Collection 分页、机构 API、标识符提取、Manifest URL 模板等方法。
- 将机构特定 URL、字段路径、分页参数和模板放入配置，尽量复用同一套 Python 处理代码。
- 保存调查过程、成功证据和失败记录，避免后续维护只依赖聊天上下文。
- 对共享平台增加明确的机构范围配置，避免遍历时丢失子站路径，或把不同机构的资源混为同一个来源。

### 3.2 已支持的主要发现方法

1. 直接 Manifest，以及 HTML/JSON 中明确声明的 IIIF 链接。
2. Presentation Collection 的成员、嵌套 Collection 和声明的分页链接。
3. Change Discovery 活动流和分页。
4. HTML 链接、数据属性、嵌入 JSON-LD，以及有预算限制的同站遍历。
5. JSON 目录 API 分页，提取记录 ID 或直接 Manifest 链接。
6. HTML 目录及条目详情中的 ID、链接或迁移信息。
7. XML、RSS、OAI-PMH 目录，通过命名空间和字段路径提取标识符；支持配置的数字分页或 OAI 延续令牌。
8. 根据已核验的 ID→Manifest 模板生成候选地址，再请求并校验响应。

这些方法的组合并不保证适用于所有机构；成功找到一份 Manifest 也不代表完成全馆枚举。

## 5. 按 Arsha 的需求，我们增加了哪些输出

### 5.1 文献、图片和 OCR 画像的关系

```text
common_records.jsonl：文献主记录，以 record_id 标识
├── common_media.jsonl：图像记录，通过 record_id 找到文献
│   └── 每张图另有 resource_id、Canvas ID、下载 URL 和图像服务信息
├── ocr_document_profiles.jsonl：文献的 OCR 特征描述，通过 record_id 关联
└── institution_reference_texts.jsonl：机构提供的 OCR/转录参考
    ├── 页面级：用 resource_id 和 Canvas ID 与具体图片关联
    └── 文献级：保留整体范围，不强行分配给某一张图片
```

这些文件通过 ID 关联，不要求主记录中重复嵌入所有图片地址。JSONL 每行是一个 JSON 对象，适合批量处理；CSV 用于人工查看。

### 5.2 OCR 画像能提供什么

已增加或整理语言、日期与世纪、显式文字系统、印刷/手写/混合分类、文献类型，以及元数据中明确提及的 Fraktur、long s、连字等特征，并保留依据和未知状态。

这些特征主要来自元数据与规则提取，不是已经对所有图片进行了视觉识别。渗墨、破损、微缩胶卷、模糊等扫描质量仍需要图像检查；缺失信息保留为未知，不能自动认定为没有这些问题。

`ocr_ground_truth_candidates.jsonl` 是建议抽样检查的页面，不是已经制作完成的人工标准答案。机构 OCR 也不能自动视为人工逐字校正的 ground truth。

### 5.3 已有真实的图片—参考文本样例

已有历史全链路验收证据包括 BSB 的 hOCR、FromThePage 的转录，以及无页面参考文本的 EPFL 样例。

最新一轮的林茨样例进一步验证了：

- 6 份 Manifest 中保存了 **3,504 条参考文本描述**，其中 3,498 条关联到具体图像，6 条属于文献整体范围。
- 这些主要是参考地址，本轮没有逐条下载全部文本。
- 实际下载了一份正文 ALTO XML、抽取纯文本和对应 Canvas 21 的图片。
- 图片与 ALTO 页面尺寸均为 **2882×4629**；159 个词的坐标均位于图像范围内。
- 图片、参考文本、机构、Manifest、Canvas 和 `resource_id` 的关联已保存。

这证明机构图像与参考文本的交接链路可以工作；还不能保证 OCR 内容全部正确，或所有来源的外部注释格式都已覆盖。

## 6. Module 5 与最终下载目录的调整

### 权利处理

我们已经将“研究保留”和“公开再利用”分开处理。按当前项目策略，unknown 与 exclude 记录继续进入研究下游，原始权利声明、机构和限制标记始终保留。

`exclude` 表示不进入公开再利用子集，不表示从研究流水线删除。没有标明权利的内容仍标记 unknown，不改写为“无版权”。这些是程序策略及数据分类，不替代具体资源的机构条款。

### 图片样本包

```text
Module8 配置的 output_directory/
└── example/ 或 all/
    ├── with_reference/文献ID/页面ID/
    │   ├── image.jpg
    │   ├── common_record.json
    │   ├── common_media.json
    │   ├── ocr_document_profile.json
    │   ├── institution_reference_texts.json
    │   ├── institution_reference_001.xml（或 hOCR/TXT）
    │   └── institution_reference_001.txt
    ├── without_reference/文献ID/页面ID/
    │   └── 图片及上述三份基础 JSON
    ├── reference_failed/文献ID/页面ID/
    │   └── 图片及上述三份基础 JSON
    ├── download_index.jsonl
    └── download_summary.json
```

`with_reference` 要求至少成功下载一份关联的机构文本；有文本声明但获取失败的进入 `reference_failed`；没有识别出页面级文本声明的进入 `without_reference`。文献整体文本不自动成为每页标签。

另一个已经修正的问题是：Module 5、6 不再因 Manifest 与旧 SHA-256 不一致而拒绝更新后的有效数据。保留的哈希用于来源描述或文件完整性记录，不是“只允许旧内容”的准入条件。

## 8. 仍未完成、需要继续推进的内容

| 问题 | 当前实际情况 | 后续工作方向 |
|---|---|---|
| 未知机构调查依赖人和 AI 对话 | 有经验库与可执行配方，尚无运行时自主调查 | 增加可独立运行的调查流程：读取证据、提出配方、确定性验证、失败留档、成功后保存 |
| 发现成功不等于全馆枚举 | 部分来源仅覆盖指定项目、查询条件或 RSS 子集 | 为各路线记录范围、分页能力、截断原因，补足完整目录枚举 |

| 图片 URL 可能只是预览 | 默认 M7/M8 会保留并下载来源给出的版本 | 最新批次增加了显式读取 Image 服务的高清样例辅助步骤；生产默认尚未统一优先高清 |
| 图片和 OCR 对齐不总能保证 | 已实现关联与实测样例；有些文本仅为文献整体范围 | 继续扩展明确的页面级关联，核对实际像素及坐标范围，保留无法对齐的原因 |
| 参考文本格式覆盖不完整 | 外部 AnnotationList/AnnotationPage 等尚未完整遍历 | 增加可复用的注释获取和文本格式处理，避免把普通描述元数据当作 OCR |
| OCR 数据集还没有完成统计与人工验收 | 已输出画像、候选和机构参考；不代表完整训练集 | 对选定数据集统计语言、年代、字体与扫描质量，抽样检查参考文本质量 |
| 团队最终共同模式仍待确认 | Module 7 使用有版本的暂定模式 | 按团队和 Arsha 的实际输入要求调整字段，保留兼容与来源证据 |

其中“接入 AI API 自动调查陌生机构”“自动扩大机构清单”等属于后续设计方向，不能写成当前已完成功能。
