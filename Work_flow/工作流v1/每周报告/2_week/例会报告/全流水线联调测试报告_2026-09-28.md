# 结论摘要

2026 年 9 月 28 日，当前代码版本完成了一次 **Module 1 到 Module 7 的真实网络端到端运行**。运行从 94 个候选机构和 158 个候选入口开始，最终输出 18 条对象记录和 106 条媒体记录。七个模块全部正常退出，统一运行器状态为 completed，总耗时 20 分 45 秒。

核心结果如下：

- Module 1：94 个机构，158 个入口。
- Module 2：158 个入口全部检查；99 个入口能够返回 HTTP 成功响应，涉及 67 个机构；7 个入口直接返回可解析 JSON，涉及 6 个机构。

- Module 4：324 个 Manifest 全部成功获取并通过当前基础结构校验；展开为 54,654 条资源清单记录。

- 自动化测试：Module 1–7 与统一运行器共 108 项测试，全部通过。

## “完整运行”的边界

本次运行覆盖 Module 1 选出的全部 94 个机构和全部 158 个入口，但 Module 3 使用安全上限控制外部网站请求：

- 每个机构最多读取 5 页 Change Discovery；
- 每个机构最多遍历 20 个 Collection；
- 每个机构最多访问 3 个 HTML 页面，深度为 1；
- 每个机构最多处理 20 个机器生成候选入口；
- 每个机构最多保留 100 个 Manifest。

# 逐模块测试结果

## Module 1：Provider Census and Selection

**输入。** 配置包含 IIIF Registry、IIIF 官方资源指南、社区维护实现清单和项目人工维护条目。本次实际产生记录的来源是官方资源指南 69 个机构、社区清单 25 个机构；Registry 与项目人工条目在本次输入中没有产生机构记录。

**处理。** 模块保留同一机构的全部候选入口，规范化 URL，以稳定 provider_id 合并机构，并保留来源证据。

**输出。**

- providers.jsonl：94 条机构记录；
- selected_providers.jsonl：94 条本次选中机构记录；
- providers.csv：158 行入口级平面表；
- 共 158 个候选入口，其中机构主页 70、Presentation Collection 35、相关资源 32、直接 Manifest 18、机构 API 2、Change Discovery 1。

**当前问题。** 来源清单是志愿维护的，可能过时或遗漏；同名机构和项目站点仍可能被错误合并；入口角色部分依赖来源标签和启发式判断。

**改进方向。** 增加来源更新时间、可信度和失效状态；完善别名与域名级实体消歧；在初代流水线稳定后，再增加受控的网络发现补充来源。

## Module 2：Entry URL Accessibility and Validity Check

**输入。** 94 个机构的 158 个候选入口。

**处理。** 对每个入口独立请求，记录重定向、状态码、内容类型、响应时间、大小和 JSON 可解析性。

**输出。**

- checked_entry_points.jsonl：158 条完整检查记录；
- discovery_ready.jsonl：7 条可直接作为 JSON 资源处理的入口；
- manual_review.jsonl：123 条需要后续发现策略继续判断的入口；
- unavailable_entry_points.jsonl：28 条当次不可用入口。

结果分布为：reachable_non_json 92、reachable_json 7、restricted 29、unreachable 19、temporary_failure 9、response_too_large 2。HTTP 成功入口共 99 个，覆盖 67 个机构。直接可解析 JSON 覆盖 6 个机构。入口响应时间中位数为 500 ms，90 分位为 1,776.9 ms，最大为 21,312 ms。

这里的 manual_review 是输出类别名称，不表示流水线必须人工暂停。Module 3 会继续处理 HTML 和其他可解释入口；整个主流程仍是自动化的。

**当前问题。** 单次请求只能反映当时网络状态；403 可能是访问策略而非资源不存在；HTML 首页不是失败，也不能直接证明存在 IIIF；TLS、DNS、限速和区域限制没有充分拆分。

**改进方向。** 增加分时重试、缓存与条件请求；记录 DNS、TLS、robots 和认证要求；允许按主机配置限速；区分永久失效与短期网络故障。

## Module 5：Rights Identification and Filtering

**输入。** 324 个有效 Manifest 和 54,654 条资源清单。

**处理。** 自动提取 Manifest、Canvas、内容主体及服务层面的版权与许可证据，映射到统一类别，并依据 automatic-2026-09-25 策略决策。当前策略仅允许明确 public_domain 或 open_license 的记录；其他类别全部自动排除，不要求人工审核。

**输出。**

- rights_assessed_manifests.jsonl：324 条；
- allowed_manifests.jsonl：18 条；
- excluded_manifests.jsonl：306 条；
- allowed_resource_inventory.jsonl：106 条；
- rights_summary.csv：324 行。

版权类别为 unknown 202、noncommercial_or_limited 100、public_domain 10、open_license 8、in_copyright 2、institutional_terms 1、conflicting 1。允许的 18 条由 10 条 public_domain 和 8 条 open_license 组成，Manifest 保留率为 5.56%。

**解释限制。** 5.56% 是当前保守版权政策的保留率，不是代码失败率。unknown 占 62.35%，说明大量 Manifest 没有足够的机器可判定版权证据。

**当前问题。** 声明可能位于不同层级；机构条款可能需要上下文；Manifest 与 Canvas 权利可能冲突；许可可能带有地域、期限或用途限制。

**改进方向。** 完善权利继承与冲突规则，增加权利 URI 规范化和失效日期支持；对机构条款建立可复用规则；所有决策继续保留原始证据和策略版本，以便教师确认政策后重跑。

# Module 7 最终输出结构

## 对象记录

common_records.jsonl 每行表示一个 Manifest 对象，主要字段包括：

- schema_version、record_id；
- identifier 与 identifiers；
- title、titles、description、descriptions；
- creators、dates、places、languages、subjects、types；
- rights：类别、决策、策略版本和原始证据；
- source：Manifest URL、IIIF 版本、机构、发现证据；
- quality：完整度、缺失字段和警告；
- media_count 与 provenance。

对象模式版本为 iiif-time-atlas-record-0.1。

## 媒体记录

common_media.jsonl 每行表示一个 Canvas 或图片资源，主要字段包括：

- schema_version、resource_id、record_id；
- source_manifest_url 与 sequence；
- canvas.id、canvas.label；
- image.id、image.type、image.format、image.service_urls；
- rights：类别、决策与策略版本。

record_id 将媒体记录连接到对象记录。媒体模式版本为 iiif-time-atlas-media-0.1。这种两表结构避免把多张图片重复嵌入对象行，也便于下游并行下载、OCR 和图像分析。

# 对下游同学的可用性判断

当前有两种可交接数据：

1. **结构验证后的宽样本：**324 个有效 Manifest 和 54,654 条资源清单，可用于验证 Manifest、Canvas 和图片服务读取能力。这里包含被当前版权政策排除的资源，不应直接作为公开再利用数据集。
2. **版权过滤后的安全样本：**18 条对象记录和 106 条媒体记录，全部具有明确 public domain 或 open license 证据，并已完成规范化与公共模式校验。该样本适合立即推进图片读取、OCR、对象—媒体关联和下游接口测试。

后者目前只来自 Fragmentarium，因此足以验证下游程序能否工作，但不足以评价跨机构泛化。下一轮目标应是在维持明确版权证据的前提下，增加最终数据中的机构数量与元数据差异。
