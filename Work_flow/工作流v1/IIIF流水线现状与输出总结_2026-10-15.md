# 2. Module 1-4：从机构清单到有效 Manifest

## Module 1：机构清单与入口选择

**输入：** IIIF Registry、IIIF 官方资源指南、Awesome IIIF 实现清单和项目维护条目。10 月 12 日读取的来源分别为 1、69、27、0 条，合并前共 97 条，合并后为 94 个候选机构。

**处理：** 规范化、按机构证据去重，保留原始来源和全部候选链接；一个机构对应 `provider_id`，内部用动态 `endpoints[]` 保存多入口。支持人为指定机构名称或 `all`。机构同名本身不足以证明是同一机构。

**输出：** `providers.jsonl`、`selected_providers.jsonl`、`providers.csv` 和时间戳 TXT 日志。正式交给 Module 2 的是所选机构清单。

**局限：** 来源列表有快照日期，包含机构、项目、演示或工具；候选入口尚未证明是批量 API。新增机构仍需进入来源清单或人工维护清单。

## Module 2：逐入口检查

**输入：** Module 1 的 `selected_providers.jsonl`。

**处理：** 每个机构的每个入口都检查一次，保留 HTTP 状态、重定向、最终 URL、Content-Type、耗时、JSON 可解析性和失败分类。一个机构可以产生多条入口检查记录。

**输出：** `checked_entry_points.jsonl/csv`、`discovery_ready.jsonl`、`manual_review.jsonl`、`unavailable_entry_points.jsonl` 和日志。Module 3 使用完整检查文件，HTML 和失败记录也留存。

**局限：** 首页返回 HTML、403 或超时，不足以判断机构是否有 IIIF。`manual_review` 是历史分类文件名，当前记录仍可由自动发现流程继续处理。

## Module 3：入口解析与 Manifest 发现

**输入：** Module 2 的全部检查记录、人工确认入口映射和可执行机构知识配方。

**处理：** 按机构合并多入口，尝试直接 Manifest、Collection、Change Discovery、HTML/JSON 声明链接、受限网页遍历和 API+标识符+URL 模板。对 URL 去重并保存发现路径。

**输出：** `provider_discovery.jsonl/csv`、`resolved_endpoints.jsonl`、`manifest_urls.jsonl`、`unresolved_providers.jsonl` 和日志。输出合同保留 `manifest_id`、URL、机构身份与发现证据。

**局限：** 成功标准是“至少找到一个 Manifest”，不能证明已完整枚举该机构。不同路线的失败和截断会留在机构报告中。

## Module 4：Manifest 下载与基本结构校验

**输入：** Module 3 的 `manifest_urls.jsonl`。

**处理：** 下载或使用缓存，识别 Presentation 2/3，校验基本 Manifest/Canvas/图片结构，保存原始 JSON、HTTP 信息和来源，生成页面与图片资源清单。

**输出：** `validated_manifests.jsonl`、`manifest_resource_inventory.jsonl/csv`，以及无效、不可达等分类文件；原始 JSON 存入 `data/raw_manifests/`。

**局限：** 基本结构有效不等于每张图片、每份 OCR 都可下载。图片实际请求由 Module 8 检查。

# 3. Module 5-8 与统一运行器

## Module 5：版权识别与研究用途保留

从有效 Manifest 中提取原始版权证据、所在 JSON 路径和作用层级，映射到公共领域、开放许可、受限、未知、冲突等类别。按当前项目策略，记录均保留用于研究；`allow/exclude` 只控制公开再利用子集。

**输出：** `research_manifests.jsonl` 和 `research_resource_inventory.jsonl/csv` 是 Module 6 的正式输入；另有 `research_only_*`、`reuse_eligible_*` 分类、版权摘要 CSV 和日志。未知版权仍保留机构名称、来源、学术分析和公开传播限制。

权限来自项目策略和机构声明；暴露公开接口本身不自动产生任意传播或商业使用许可。

## Module 6：元数据规范化与机构文本提取

读取 Module 5 的研究保留数据和 Module 4 当前原始 JSON，保存原始 metadata，规范化标题、作者、年代、地点、语言、类型和来源。提取已支持位置中的 `seeAlso`、内嵌文本与 Annotation 文本声明，保留 Manifest/Canvas 对齐层级。

**输出：** 文献 `normalized_records.jsonl`、资源 `normalized_resources.jsonl` 和机构文本 `normalized_reference_texts.jsonl`。另有摘要 CSV、失败记录和日志。

缺失信息不补造。当前文本发现主要依赖 Manifest 已声明的内容；外部 AnnotationPage 未在 Manifest 内嵌时，不能假定已递归下载其全部文本。

## Module 7：公共模式和 OCR 交接

将 Module 6 的文献、图片、OCR 特征和机构文本组织为关联数据，校验字段、ID 和父子关系，输出完整 JSONL、便于查看的 CSV、rejection 文件和数据包清单。

**当前模式：** `provisional-0.1`，等待团队最终字段要求。记录有效、被标为 `partial` 或版权为 `unknown` 是不同问题；缺失元数据的研究记录仍可保留。

**新增能力：** 区分图片标识符、Image Service、`info.json` 与实际图片下载 URL；通过文献 ID、资源 ID、Canvas 建立图片与机构 OCR 关联。OCR 画像与训练候选含义见第 6、7 节。

## Module 8：图片与关联文本下载

消费 Module 7 的输出，支持 `download-example` 和 `download-all`。前者按清单尝试至成功得到一个样例，后者尝试全部符合条件的记录；“全部”仅指当前输入清单。

下载器检查图片文件头、超时、大小与重试，保存关联三份 JSON。存在对应机构文本时，还保存文本来源 JSON、原始 hOCR/XML/TXT 和纯文本视图。缓存用于复用现有有效图片，失败保留日志。

## 统一运行器和哈希调整

Pipeline Runner 可以依次执行 1-8、从指定模块恢复、记录命令和退出码，并在模块进程失败时停止。每个模块仍有独立配置；常规运行默认只让 Module 8 下载一个样例。

**已删除 Module 5、6 的跨模块 SHA-256 比对和旧哈希拒绝策略。** 哈希仍可用于稳定 ID、下载信息和数据包描述，但不阻止更新后的 Manifest。新增或修改原始 JSON 后仍应按模块顺序重跑，确保资源清单、版权与元数据属于同一批结果。

# 4. Manifest 发现的主要瓶颈

## 4.1 清单和指南尚未转换为完整的批量规则

很多候选入口是首页、搜索页、说明页、Viewer 或单件藏品页面。它们能导向 IIIF，但并非天然提供全馆枚举。官方指南常说明“搜索藏品、打开详情、复制 Manifest”，仍需要补齐自动搜索、分页和对象 ID 枚举。

当前已保存官方指南快照的 **69 个机构/资源条目**，以及说明、链接和候选技能。它们大部分仍是调查证据；当前可执行知识库主要包含 EPFL Plume 和 Art Institute of Chicago 两个配方。**存入知识库的文档不等于已实现和验证的批量下载能力。**

## 4.2 HTML 发现深度和候选筛选有限

默认配置：每机构最多 3 个 HTML 页面、深度 1、每页最多 50 个候选、每机构最多 20 个机器候选；Change Discovery 最多 5 页、Collection 最多 20 个、Manifest 最多 100 条。部分预算可能在机构的多条路线分别触发，应以运行报告的实际计数为准。

首页到搜索结果、再到详情页经常超过此范围。与此同时，候选筛选也会错误请求 CSS、JavaScript 或文档 URL。例如 Austrian National Library 的失败日志含样式表、脚本及未展开的模板片段。这说明需要提高候选语义和路由识别，单纯增加深度会放大无效请求。

## 4.3 不同目录平台需要不同的枚举方式

机构可能依靠 Omeka S、分页 REST API、搜索接口、SRU、Viewer 配置或 URL 模板。IIIF 统一数字对象和图像的表达方式，但不能从任意机构首页自动推出所有对象 ID。

Image API 的 `info.json` 说明一张图的服务信息，不能算作 Presentation Manifest。机构只有图片服务或存在登录/API Key 要求时，也需要明确记录其能力与边界。

## 4.4 当前网络与覆盖范围限制

最新 Module 2 的 158 条结果为：JSON 可达 7、非 JSON 可达 85、受限 36、临时失败 6、不可达 23、响应过大 1。入口类别不等于机构类别，同一机构可能有多条不同结果。

83 个 unresolved 机构按报告保留的代表入口结果分为：HTML 可达 49、受限 16、不可达 13、临时失败 4、响应过大 1。该统计用于理解主要状态，不能代替对其全部入口的复核。

## 4.5 当前指标应如何读

| 指标 | 本次值 | 含义与局限 |
|:---|:---|:---|
| 机构入口可达率 | 62/94 = 66.0% | 仅限清单中的入口和该次网络状态 |
| JSON 入口机构占比 | 6/94 = 6.4% | HTML/API 发现后可能提高 |
| 机构发现成功率 | 11/94 = 11.7% | 当前限制下至少发现一个 Manifest |
| 机构探索截断情况 | 39/94 触发上限 | 不是完整机构收割 |
| Manifest 基本结构通过率 | 336/336 = 100% | 仅验证这批候选，未验证全部图片字节 |

JSON 占比不是最终目标：可从 HTML 或机构 API 取得有效 Manifest 同样是发现成功。图片下载率、参考文本覆盖率和训练对数量必须继续由下游实测。

## 5.2 已有经验：EPFL 与 Chicago

EPFL 的初始主页探索没有进入足够深的藏品详情页。后来识别其 Omeka S 平台，通过 `https://plume.epfl.ch/api/items` 枚举 `o:id`，构建候选 Manifest URL，再用实际响应验证。该平台 API 用于找对象 ID，取得的 Manifest 仍然遵循 IIIF。

通用实现已经把“API 分页、JSON 路径取值、标识符筛选、URL 模板展开、Manifest 类型确认”与机构 URL/参数分开，并在 Chicago API 上复用。同一机构的少量成功和两个机构间迁移，只能证明这一路径可行，尚不足以证明普遍泛化。

## 5.3 后续采用三层能力

1. **通用 IIIF 技能：** Manifest、Collection、Change Discovery、明确 HTML/JSON 链接和 JSON-LD。
2. **平台/API 技能：** Omeka S、目录 API 分页、搜索结果枚举、Viewer 配置和 ID 到 Manifest 模板。
3. **机构配置：** API URL、记录路径、ID 字段、分页参数、过滤条件、模板与来源证据。

AI 调查未知机构时，应先看官方指南和目标站点，再提出路线，执行 HTTP/JSON/IIIF 验证，验证成功后保存可复用过程与机构配置。当前这种 AI 调查主要由 Codex 辅助完成；自动流水线中尚未形成对任意未知机构调用 LLM API、调查并自动写回知识库的完整闭环。

优先改进 API/平台识别和候选质量，再按机构调节深度、分页与限额；扩大规模时补齐持久检查点、恢复位置和明确完成条件。保持 Module 3 的 Manifest 输出合同稳定，可减少下游因新增发现方法而反复改动。

# 6. Module 7 最终交接数据应该是什么

正式无损格式是 **JSONL：一行一个 JSON 对象**；CSV 用于查看和交换。字段缺失应保留 `null`、`unknown` 或明确的质量状态。以下字段采用当前代码的实际层级，不能把点号路径误写成顶层字段。

## 6.1 文献、图片、画像和参考文本的关系

```text
common_records.jsonl：每个 Manifest 一条文献记录
  record_id
    +-- common_media.jsonl：每张图/资源一条
    |     record_id + resource_id + canvas.id
    |       +-- institution_reference_texts.jsonl
    |             record_id + resource_id + canvas.id
    +-- ocr_document_profiles.jsonl：每份文献的 OCR 背景
          record_id
```

`media_count` 只表示图片记录数量；寻找具体图片时，用 `common_media.record_id` 查询文献的全部媒体。机构文本进一步通过 `resource_id` 与具体资源关联，只有文献级别的文本要保留 `alignment_scope=manifest`，不能直接冒充逐页对齐。

## 6.2 四类主要文件

**`common_records.jsonl`：文献主记录。**

- `record_id`：稳定的文献 ID。
- `object`：标题、描述、作者、日期、地点、主题、类型和语言。
- `source`：原始 Manifest URL、机构、Presentation 版本和发现证据。
- `rights`：版权类别、研究保留、学术分析、公开传播与商业用途标记。
- `media_count`、`quality`、`provenance`：数量、完整性与处理来源。

**`common_media.jsonl`：具体图片记录。**

- `resource_id`、`record_id`：图片资源 ID 与所属文献 ID。
- `sequence`、`canvas.id`、`canvas.label`：页面顺序、Canvas URL 与标签；内部序号通常从 0 开始。
- `image.source_id`：Manifest 原始 body ID；`image.service_urls`：图片服务基础地址。
- `image.info_json_url`：图片服务说明；`image.download_url`：请求图片字节的 URL，`image.id` 为兼容字段。
- `rights`、`source_manifest_url`：图片权限与来源。当前映射不统一输出 width/height，不能将其写成每条必有字段。

**`ocr_document_profiles.jsonl`：OCR 文献画像。** 保存文献语言、年代与世纪、书体、印刷/手写类别、文献类型、媒体数量、来源与权限。Fraktur、long s、连字等以元数据证据为准；缩微胶卷、透印、破损、倾斜或模糊需看图，未检查时标为未知。关键词规则是证据性分类，不是训练得到的视觉判断。

**`institution_reference_texts.jsonl`：机构 OCR/转录引用。** 包含文本 ID、文献/图片 ID、Canvas、文本 URL 或内嵌文本、格式、语言、对齐范围、来源与权限。当前状态 `institution_provided_ocr_reference` 表示机构参考文本，不能自动解释为人工校正真值。

其他输出包括：

- `ocr_ground_truth_candidates.jsonl/csv`：代表页候选。
- `ocr_dataset_summary.json`：语言、年代、类别和字段覆盖率汇总。
- rejection 文件、`dataset_manifest.json` 和日志：错误与数据包信息。

```text
        image.jpg
        common_record.json
        common_media.json
        ocr_document_profile.json
    reference_failed/
      <record_id>/<sequence>_<resource_id>/
        image.jpg + 对应三份 JSON
```

`image.jpg` 是常见形式，实际扩展名随下载格式变化。原始机构文本也可能是 XML、TXT 或内嵌内容；抽取后的 TXT 便于读取，但不取代原始 hOCR 中的坐标与 confidence。

## 7.1 三类目录和下载记录

- **`with_reference`：** 图片与至少一份关联机构文本下载成功；仍需核对页级对齐和文本质量。
- **`without_reference`：** 当前数据没有可用的关联机构文本声明。
- **`reference_failed`：** 有关联声明，但机构文本下载失败；普通模式下仍可保留图片。

生成专用于训练的样例时，将配置设为 `"require_reference_text": true`。程序会跳过没有关联文本的记录，并在文本不可下载时记录失败，不把该记录导出为成功训练样例。若整个清单没有可用配对，运行会失败并给出日志。

每次运行还输出 `download_index.jsonl`、`failed_downloads.jsonl`、`skipped_downloads.jsonl`、`reference_text_failures.jsonl`、`download_summary.json` 和时间戳 TXT 日志。它们分别用于定位成功包、失败、跳过及总计。

## 7.2 BSB 参考样例与 ground truth 的界限

此前曾选用 BSB 的 Manifest `bsb12188327`，以 Canvas 10 对应图片和机构 hOCR 验证 Module 6-8。历史观察为 1 张图片、1 份 hOCR、失败 0；该示例生成目录当前未保留，本报告不把旧链接当作现存文件。

- 历史来源：[BSB Manifest 完整链接](https://api.digitale-sammlungen.de/iiif/presentation/v2/bsb12188327/manifest)。
- 对应文本：[Canvas 10 的机构 hOCR](https://api.digitale-sammlungen.de/ocr/bsb12188327/10)。

Arsha 可用此类配对试运行 OCR 或建立候选训练集。评估引擎的绝对准确率时，还需要确认参考文本是否人工校对、页面是否一致，并将开发样本与最终测试样本隔离。`ocr_ground_truth_candidates` 是选页建议；机构 OCR 是参考标签；经过核验的人工转录才是严格意义的 gold ground truth。
