# 统一命令行启动说明

2026-11-05。修改前的本地保存点：`ff46048`，提交名“期中汇报使用版本”。

在项目根目录执行下面的命令。CMD 和 PowerShell 都可以使用 `python pipeline.py`，程序会自动使用项目虚拟环境；Windows 还提供 `pipeline.cmd`，PowerShell 中写 ` .\pipeline.cmd`。

## 首次安装

```text
python pipeline.py --setup
```

这一步统一创建/复用虚拟环境并安装八个模块及运行器。已有正确环境可直接运行，不必每个模块分别输入安装或激活命令。安装本身需要可用的 Python 和依赖下载网络。

## 一条命令运行

```text
python pipeline.py --modules 1-8 --institution "Ecole Polytechnique Fédérale de Lausanne (EPFL)" --max-manifests 6 --download example
```

机构名称来自机构清单，`--institution` 可重复多次，或写 `all`。`--max-manifests` 是每个来源的发现上限，不是全馆数量。默认下载一张样例，是整个合格输出中的一张，而非每家一张。

程序打印运行目录，所有输入输出、原始 Manifest、配置快照和日志都在该目录下，不覆盖原模块默认目录。

## 选择模块数量或范围

```text
python pipeline.py --module-count 3 --institution all --max-manifests 2
python pipeline.py --modules 1-4 --institution all --max-manifests 2
python pipeline.py --modules 6,7,8 --run-dir "之前打印的运行目录" --resume
python pipeline.py --from-module 4 --to-module 8 --run-dir "之前打印的运行目录" --resume
```

`--module-count 3` 表示前3个模块；`--modules` 支持范围和逗号列表。跳过前面的模块时，必须已有本次运行对应的上游文件；不会静默混入另一批旧数据。续跑是模块边界的重新执行，不保证某模块内部任意网络请求位置的恢复。

## 重用数据、下载全部、只要参考文本样本

```text
python pipeline.py --modules 8 --run-dir "之前打印的运行目录" --resume --download all
python pipeline.py --modules 8 --run-dir "之前打印的运行目录" --resume --download example --require-reference
```

“全部”仅指 Module 7 本次已导出的图像记录。`--require-reference` 要求成功取得与页面关联的机构文本；机构 OCR 不自动等于人工校正答案。

## 固定 Manifest 的小规模全链路演示

```text
python pipeline.py --modules 1-8 --manifest-url https://plume.epfl.ch/iiif/3/44/manifest --max-manifests 1
```

这验证模块交接，不能作为从陌生机构首页发现 Manifest 的能力证明。`--manifest-url` 可重复；指定固定种子时只建立这些种子的来源输入，不请求 Registry。

## 先查看配置，不发起采集

```text
python pipeline.py --modules 1-3 --institution all --max-manifests 2 --dry-run
```

查看生成的 `configs/` 和 `pipeline.json`。准备后的目录再执行时需要 `--resume`。要强制重新获取 Module 4 的 Manifest，加 `--force-refresh`。

## 输出在哪里

```text
运行目录/
  pipeline.json
  configs/module_1.json ... module_8.json
  module_1/output/ ... module_8/output/
  module_1/log/ ... module_8/log/
  module_4/raw_manifests/
  log/Pipeline_电脑时间_log.json
```

Module 8 的实际图片在 `module_8/output/example/` 或 `all/`，再分为 `with_reference`、`without_reference`、`reference_failed`。每张成功图片附带三份 JSON。

高级用户仍可使用 `--config 自己的pipeline.json --modules 1-4`。该模式采用已有配置路径，不自动隔离输出，也不接受新运行的机构、数量等覆盖参数。

## 可选：让 Module 3 使用自己的 LLM API

```text
python pipeline.py --modules 1-3 --institution "机构名称" --llm --llm-model "自己的模型ID" --llm-key-prompt
python pipeline.py --modules 3 --run-dir "已有运行目录" --resume --llm --llm-model "自己的模型ID" --llm-key-file .secrets/llm-token.txt
python pipeline.py --modules 3 --run-dir "已有运行目录" --resume --no-llm
```

默认不调用 LLM。先运行现有方法，未解决的机构再进入调查。密钥可以隐藏输入、读环境变量，或从本地文件读取；`.secrets/` 不纳入 Git。API 付费与 ChatGPT/Codex 登录分开，需自己提供可用模型与 API 凭据。

默认调查最多3家，每家6次模型调用、16次公开 GET，成功方法最多接受3份 Manifest 样例，并受发现上限限制。支持 `--llm-max-providers`、`--llm-max-rounds`、`--llm-max-fetches`。方法通过实际检查后写入独立学习库，下次可无密钥复用；输出格式不变。

默认 OpenAI Responses；其他兼容服务可使用 `--llm-mode chat_completions --llm-base-url https://自己的服务/v1`。`--llm-web-search` 仅适用于支持网页搜索工具的 Responses 服务和模型。详细流程、保存格式和限制见 [Module 3 接口说明](../Module_3/LLM接口与知识复用说明.md)。
