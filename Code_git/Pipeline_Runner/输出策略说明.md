# 流水线输出策略

## Manifest 内容更新

Module 5 和 Module 6 始终读取 Module 4 当前缓存的原始 Manifest，不再执行跨模块
SHA-256 一致性校验，也不会因为 Manifest 内容更新而拒绝记录。Module 4 输出中已有
的 SHA-256 可以继续作为下载来源的描述信息保存，但它不参与下游准入判断。

这样重新下载或替换后的有效 Manifest 会直接进入版权识别、元数据规范化和后续
输出。真正会导致失败的情况只包括文件不存在、JSON 无法解析或不满足相应模块的
数据结构要求。

## Reference 数据交接

- Module 6 输出 `normalized_reference_texts.jsonl`，保存 Manifest/Canvas、机构、
  原始 OCR 或转录 URL、格式和对齐范围；
- Module 7 输出 `institution_reference_texts.jsonl`，并用 `record_id`、
  `resource_id` 和 Canvas ID 将文本精确关联到 `common_record` 与
  `common_media`；
- Module 8 下载图片、原始 hOCR/XML/文本和纯文本视图，并生成独立 JSON。

机构 OCR 被标记为 `institution_provided_ocr_reference`。该标记表示来源可信且
页面对齐，不自动表示文本经过人工逐字校对。

## Module 8 最终目录

无论使用 `download-example` 还是 `download-all`，输出都按实际结果分类：

```text
example/ 或 all/
├── with_reference/
│   └── record_id/page_resource_id/
│       ├── image.*
│       ├── common_record.json
│       ├── common_media.json
│       ├── ocr_document_profile.json
│       ├── institution_reference_texts.json
│       ├── institution_reference_001.hocr.html（或 XML/TXT）
│       └── institution_reference_001.txt
├── without_reference/
│   └── record_id/page_resource_id/
│       ├── image.*
│       ├── common_record.json
│       ├── common_media.json
│       └── ocr_document_profile.json
└── reference_failed/
    └── record_id/page_resource_id/
        ├── image.*
        ├── common_record.json
        ├── common_media.json
        └── ocr_document_profile.json
```

`with_reference` 只接收至少成功下载一份机构文本的图片；存在文本声明但下载失败
的图片进入 `reference_failed`，并在 `reference_text_failures.jsonl` 中记录原因。
没有机构文本声明的图片进入 `without_reference`。训练集运行应设置：

```json
"require_reference_text": true
```

这样 Module 8 只生成具有可下载机构 reference 的图片—文本样本。
