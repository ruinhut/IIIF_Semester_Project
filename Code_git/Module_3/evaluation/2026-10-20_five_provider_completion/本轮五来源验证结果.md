## 找到入口的方法

1. **Ghent**：从 IIIF 指南和 Biblissima 的 Ghent 筛选目录入手，读取结果元素的 `data-manifest` 属性，获得 Ghent 原站的 Manifest。分页使用 `from` 偏移量。覆盖范围是该聚合目录收录的 Ghent 资源。
2. **St Andrews**：检查其公开检索网页加载的应用脚本，确定 Funnelback 搜索 API、检索集合、分页参数和条目标识符路径；筛选已发布的图片记录，再请求原站的 `/{IRN}/manifest`。本次读取两页、20 条候选记录，得到 4 个可用 Manifest；下一页返回 HTTP 429，停止继续请求。因此本来源是**方法已验证，但采集部分完成且受限流影响**。
3. **三个 Yale 博物馆**：查阅 Yale LUX 官方客户端和搜索配置，用 `memberOf` 按馆筛选有图片的对象；读取对象的 Linked Art 详情中明确声明的 Manifest 链接，再按本馆命名空间过滤。三个来源复用同一算法，分别配置 `ycba/obj`、`ypm/nat`、`yuag/obj`。

已经将五份可执行配置追加到 `Module_3/config/discovery_knowledge.json`。原有 23 份知识条目保持不变，现在为 28 份；原有 18 份入口配置也全部保持不变，包括此前 EPFL 等方法。保存的是可复用操作与来源配置，本轮没有接入运行时大语言模型 API。

## 累计进度与限制

累计验证成功的清单条目由 **49 → 54 / 94**，未解决由 **45 → 40**。这是已有来源清单的累计证据口径，不是全球 IIIF 机构总数，也不是 54 家互不重复的机构；本清单含聚合平台和别名。三个 Yale 博物馆是不同的既有条目，但共享一个 LUX 发现流程；另一条 British Art 别名没有额外计数。今天没有重验此前全部成功条目。

St Andrews 的原始技能审计中 `truncated=false` 没有反映分页 HTTP 429，判断是否完整必须同时看 `failure_counts` 和请求日志，本报告明确记录为部分结果。其 API 声明的检索总数不能当作可下载 Manifest 总数。其他来源亦为设定数量上限的小样本验证。

备选调查中仍遇到 401、403、空响应、TLS 证书链错误或批量枚举未确定，详见 `unresolved_investigations.json`；这些来源均未冒充本轮成功。没有关闭证书校验或绕过身份验证。本轮更改保存在本地，尚未同步 GitHub。
