## 找到入口的方法

1. **梵蒂冈**：从官方指南进入原站，检查网页加载的脚本，找到公开精选目录 JSON。其 `result` 是按书架号组织的字典，读取每条 `id` 后请求原站 Manifest。本次目录有 14 条，验证其中 6 条；未声称遍历整个梵蒂冈馆藏。
2. **Getty**：通过公开 SPARQL 接口分页查询文物对象 ID，读取对象的 Linked Art 详情，再取得 `subject_of` 中明确声明的 IIIF Manifest 链接。限定为 Getty Museum 的这类对象，不是 Getty 全部研究与档案资源。
3. **Cultural Japan**：根据其公开 OpenAPI 文档，检索带 IIIF 的记录，直接读取其声明的上游原站 Manifest。使用分页和去重，拒绝返回网页、404 或非 Manifest 的候选项。
4. **Harvard Art Museums**：复用上面的公开索引，按 Harvard 来源筛选，并限定为 Harvard 原站的 Manifest 地址。这是索引收录的子集，不是绕过 API 密钥获取全部馆藏。
5. **NGA Library**：按官方指南检查图书馆目录，找到公开 Primo JSON 搜索接口。提取 MMS 标识符，验证图书馆原站 Manifest 路由。本次 `grandezze` 查询有 18 条目录记录，包括实体书，最终验证 3 份数字文献；不能把目录匹配数当作可下载数字书数量。

## 程序与测试

- **Module 6**：Getty 将目录 JSON 链接声明为 `Text`，原先会被误判为参考文本。现在类型名本身不足以证明它是 OCR；无格式或 JSON 资源需要明确转录信号。原始 Manifest 链接仍保留，hOCR、ALTO 和明确转录继续支持。
- **M3–8 自动测试 173 项通过，另有 7 个子测试通过**。这不是整个项目所有模块的测试总数。
- **Module 4 独立联网获取并校验 26/26**，缓存命中为 0。之后仅为刷新诊断文字，M3 重用了当天响应快照；没有用它代替 M4 的独立验证。
- **最终 Module 8 实际下载 5/5**，没有缓存命中或下载失败；五张图片均可解码，15 份 JSON 的结构和关联检查均通过。

## 必须保留的限制

**NGA 图片实际为 2818×4096，小于 Canvas 声明的 3302×4800。** 已在 `image_decode_verification.json` 记录，不称为原始分辨率；使用页面坐标时应按实际图片尺寸换算。其余四张样例与声明尺寸相符，但 Getty 和 Harvard 样例本身分辨率较小，也不能据此声称得到档案原图。

首轮曾选择 Europeana：已取得并校验六份 Manifest，但样例的原馆图片返回 403；后续检查还遇到旧地址、非图片响应和 TLS 失败。因此换用 NGA 补足本轮五个完整链路来源，**没有把 Europeana 计入这五个成功条目**。它属于“Manifest 已有部分进展、图片链路尚未完成”，不是完全找不到 Manifest。首轮日志与失败证据保留在 `first_attempt/initial_europeana_batch/`。

Folger 与 Leeds 也存在能请求的单条 Manifest，但本轮尚未验证批量枚举；其他受限、停用或迁移来源见 `unresolved_investigations.json`。没有绕过人机验证、身份验证或关闭证书校验。
