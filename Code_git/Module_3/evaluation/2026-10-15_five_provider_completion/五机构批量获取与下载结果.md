# 五个机构批量发现与下载验证结果

这五家现在均已具有可执行的批量发现配方，并各取得 20 个不同 Manifest。100 个 Manifest 全部通过 Module 4 验证。

| 机构 | 发现 Manifest | 验证通过 | 样本声明的图片资源 | 实际下载样例 |
|---|---:|---:|---:|---:|
| Göttingen University Collections | 20 | 20 | 9,540 | 1 |
| Leiden University | 20 | 20 | 2,020 | 1 |
| National Library of Wales | 20 | 20 | 104 | 1 |
| Universitaet Jena | 20 | 20 | 12,625 | 1 |
| Utrecht University Library | 20 | 20 | 2,543 | 1 |

合计：100 个有效 Manifest、26,832 个声明图片资源；实际下载 5 张图片，失败 0。图片已经与文献主记录、媒体记录和 OCR 特征描述关联。

## 每家是怎样获取的

- Göttingen：分页读取全站检索页中的文献 ID，生成并验证标准 Manifest URL。
- Leiden：按书籍对象类型检索目录，读取实际 item ID；允许旧 Manifest URL 自动跳转到迁移后的 Alma 地址。
- Wales：公开 Primo JSON 搜索 → 查看器 ID → IIIF 资源；若返回 Collection，继续遍历其子 Manifest。
- Utrecht：完整对象清单 → 公开访问条目的对象 ID → Presentation 3 Manifest。
- Jena：MyCoRe 对象分页 API → 每个对象的 derivative ID → Presentation Manifest。

## 这次解决了哪些通用问题

1. JSON 数组中提取 ID、按正则从 URL 提取 ID、调用第二层详情 API。
2. 定向读取 HTML 目录，并按公开访问标记筛选；基于实际翻页链接判断是否还有下一页。
3. 目录边读边验证，不先把所有目录页抓完再产生输出；识别重复返回同一页的分页错误。
4. API 返回 Collection 时复用现有 IIIF 遍历器，保持 Module 3 的下游输出契约。
5. Module 8 增加标准 Image Service 回退。Göttingen、Wales 的旧图片直链返回 404，Leiden 的 JP2 请求返回 400；读取各自已声明的 info.json 后均成功取得 JPEG。没有加入机构名称分支，也没有改 Module 4–7 的解析。

## 真实失败与范围

- Jena 的一次复跑曾因目录接口 HTTP 500 而失败；后续独立重试成功。失败批次和成功重试均保留，combined/batch_sources.json 指明合并来源。不能把这一结果理解成网站永远不会超时。
- 本次是每家 20 个 Manifest 的验证。26,832 是这些 Manifest 声明的图片资源数量，本次没有逐张下载这些资源。
- Leiden 当前配方覆盖书籍类型；Wales 当前配方覆盖已验证的目录查询结果，不能据此宣称已枚举全馆。
- Utrecht 完整清单包含 29,357 个不同对象 ID，25,564 条标为公开访问。这些目录数量并不等于已验证 Manifest 数量。
- 生产知识库的源目录预算与本次 20 条输出限额分开。增大测试输出只需修改配置/运行参数，不必为每家写新 Python 分支。

## 输出在哪里

- provider_results.csv：逐机构统计。
- combined/module3/output/manifest_urls.jsonl：100 个 Manifest URL。
- final_validation/module4/output/validated_manifests.jsonl：100 个验证记录。
- final_validation/module4/output/manifest_resource_inventory.jsonl：26,832 条图片资源清单。
- sample_downloads.json：每张图片的本地绝对路径、机构、Manifest ID、实际图片 URL 和回退尝试记录。
- download_examples/module8/output/all/without_reference/：5 张图片及各自的三份 JSON。
- live/、validation/、final_validation/、jena_recovery/：原始 HTTP 证据、逐机构检查点和模块日志。
- 运行命令.txt：可直接复制的 PowerShell 指令。

## 检查结果

Module 3 自动测试 44 项通过；Module 8 自动测试 16 项通过。Module 5–7 的真实样例运行均为 5 条输入、5 条有效输出；Module 8 最终重新联网下载 5 张图片，缓存命中 0、失败 0。

原来 69 个未解决清单条目减少为 64 个；这仍是清单条目数量，不自动等同于去重后的机构数量。
